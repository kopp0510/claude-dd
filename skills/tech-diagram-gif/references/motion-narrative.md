| 模式 | 適用 | 結構 |
|------|------|------|
| **循環流動**（預設） | 內部溝通、快速交付 | 全圖靜態 + 小球/dash 沿線循環（SKILL.md 第 3 步） |

## 建置 → 營運五幕結構

ByteByteGo 實測歸納：動畫面積僅佔畫布 1.2–3.6%、節點/文字/鏡頭全程不動 —
「高級感」來自克制，不是來自更多動效。

1. **開場**：只有節點與分組，**所有連線缺席**（幀 0 可讀完整拓撲）
2. **建置**：連線按語意順序逐條「畫入」（stroke-dashoffset 從全長收到 0），
   畫完才顯示箭頭；同時最多 1–3 條在畫（依複雜度）
3. **定格**：拓撲完成，短暫停頓
4. **營運**（佔總長 60% 以上）：每條線出現流動效果（小球或軌+亮頭），等速循環
5. **重置**：流動不停的同時全圖淡出 → 回到幀 0 循環（淡出幀約 4–5 幀）

總長建議 5–6 秒；所有時間點仍須整除總長（GIF 無縫循環，見 SKILL.md 第 3 步）。

## 軌 + 亮頭雙層流動（dash 模式的進階版）

實線上疊兩層 dash，取代單層脈衝：

- **軌（body）**：來源色系，寬 = 來源線寬 ×1.5（上限 ~4px），opacity ~.9，
  dash 如 `16 25`（週期 41）
- **亮頭（head）**：近白亮色，寬 ~2px，dash 如 `6 35`（同週期 41），
  **dashoffset = 軌的 offset − 10** → 亮段永遠壓在軌段前緣，形成「發亮的封包頭」
- 兩層同速前進（如每幀 −6 單位）；**週期與步進互質**（41 與 6）→ 循環內相位不重複
- 兩層都不帶 marker / filter / glow

Style 8 的流動識別可用「gem-tracer」概念：小球即寶石游標，僅光暈可帶 filter。

## 品質準則

- 節點、文字、容器、箭頭 marker、鏡頭全程不動 — 只有連線相關圖層在動
- 每幀不重複（定格截圖時檢查相鄰幀相異）；營運段允許相位循環
- 檔案目標 ~500KB 級；超標優先降總長或降色數，**不縮尺寸**（SKILL.md 第 5 步規則）
- 幀 0 必須與營運中任一幀肉眼可辨（避免「看起來沒在動的開場」）
