## 處置

- **Important 去重後是四件，都採納、級別沿用，都修在說明與註解，大小檢查的判斷邏輯沒有動**：
  本機打一個 `v*` tag 就算發版（A1、B1、C1、D1）；「hook 擋不到的」清單四處講法不一致（C2、D2）；「⑯ 跑這一層的三個檔」不對（C3）；`/dd-init` Phase 3 的位置規則會把這支 hook 判成要搬（D3）。
- **本機 tag 那一件為什麼不改取 tag 的寫法**（A 建議把樣式收緊成 `v[0-9]*`、D 建議只接受 `HEAD` 的祖先）：
  1. 兩種收緊都擋不住 A 實跑的那個情境：調高上限檔的 commit 就在這條 branch 上，再打一個版本號更大、形狀正常的 tag。那正是發版時會做的動作，腳本分不出來。
  2. `git tag --list 'v*' --sort=-v:refname | head -1` 是 `ci.yml` 另外兩步在用的同一個寫法（「CHANGELOG 已發布區塊不可改動」與「dd-init 蓋章區塊改了就要跳 dd-loop-rev」），只改這一處，三個地方對「最新發版」的定義就不一樣了。
     `ci.yml` 那一步的註解寫了它不用 `git describe --abbrev=0` 的理由（取的是「最近」的 tag，會解到 `pre-prune-*` 這類非版本 tag 身上）；D 建議的寫法帶 `--match 'v*'`，不受那個理由影響，所以這一點不是我駁回的依據。
  3. 改「哪些 tag 算數」是行為改變，要有情境釘住；清單以外的測試照進度表規則要先問使用者。
  處置是把實際的範圍寫清楚：「最新的 `v*` tag」= 本機所有 `v` 開頭的 tag 裡照版本號排最大的那一個，不查它推了沒、是不是版本號的形狀、在不在這條 branch 的歷史裡；後果列進「繞得過的路」。
  ⚠️ 這一件動到使用者選「乙」時我給的說法（「檢查讀的是最新發版 tag 那一版的數字」）：實際上打一個本機 tag 就算，gate-guard 不管 `git tag`，`git push --tags` 會把它帶上 CI。回報時放在前面講。這一段沒有去擴 gate-guard（它是部署內容）。

## 這一段自己犯的錯（給步驟 7）

1. **帶著一個紅燈 commit**（`d0e72b1`）。本機照 ci.yml 逐 step 跑的腳本每步都印 rc、最後印「沒過的 step 數」，但整支一律回 0；我用 `&&` 把 `git commit` 接在後面，彙總印了 1 照樣 commit，訊息還寫了「全部 rc=0」。下一個 commit `abf3d18` 更正。腳本已改成有一步沒過就回非 0。
2. **那個紅燈本身**：`tests/CLAUDE.md` 的 `test-gate.sh` 那一列原本就有 2 個「→」又含 commit 與 review 兩個字，我加的說明多了一個「→」，整行被 CI「迴圈步數第五方」當成迴圈的箭頭摘要。
3. **同一張清單寫了四處，補的時候只補一處**（C2、D2）：`83c18ee` 把「不經過 pre-commit 的 commit」補進 `scripts/githooks/CLAUDE.md`，`ci.yml` 的註解、CHANGELOG、架構文件還是只列兩種。現在另外三處只舉例並指到那一處。
4. **機制憑印象寫**（B3、C4）：「不排序拿到最舊的 tag」沒有跑過；⑯ 的資料裡 `v0.0.0` 剛好既是最舊的、也是字典序第一個，兩種說法在那裡分不出來。
5. **描述測試涵蓋的範圍時沒有對測試碼**（C3）：寫了「⑯ 跑這一層的三個檔」，實際上上限檔是測試自己寫的。
6. **步驟 4 期間自己的三個失誤**，都是當場對不上才發現的：
   - 拿「開頭直接 `exit 0`」的 gate 變異跑測試，看到 ⑯ 的 ❌ 是 0，差點記成「gate 的變異不影響 ⑯」。實際上測試在 ⑯ 之前就結束了，輸出裡一行 ⑯ 都沒有。先數那一節的 ✅ 才看得出來。
   - 把「往檔尾加一節」接在 `tail -c 200 … | cut -c1-80 &&` 後面：`tail -c` 把一個多位元組字元切斷，`cut` 回非 0，後面的 append 被跳過，沒有任何錯誤訊息；是後面的 `grep -c` 回 0 才發現。
   - 改檔腳本裡有一批是「新字串開頭就是舊字串」（在既有段落後面加字），誤把那一批重跑一次，設計文件多出一份一模一樣的段落；`grep -c` 該是 1 的回 2 才發現。腳本已加上「已經套用過就不再套」的檢查。
