## 發現

Critical 0 / Important 3 / Smell 1 — 範圍：adbb124..工作目錄（S1.6）。重點看根目錄 CLAUDE.md「新增 Skill 步驟」第 3 步結尾新補的乾跑那兩行（diff.txt 第 33–34 行）。

**Important｜CLAUDE.md 第 3 步「派工時寫明「」裡要跟檔案一字不差…」（diff.txt:33）｜「一字不差」實際怎麼核對沒寫。同一步前面那句，以及 security-audit 的做法，都會把下一個 session 帶去用 `grep -F`，可是 `grep -F` 一次只比一行，跨行的原句一定對不到。**
- 證據：同一步寫「原句 `grep -F` 得到只證明引文存在」（diff.txt:118）；`skills/security-audit/CLAUDE.md:26` 寫「拿本檔「」裡的英文原句 `grep -F` 新版，找不到的就是被改了」。S1.6 自己判定「對得到」用的是另一種比法：「去掉所有空白與換行後看是不是原檔的子字串」（diff.txt:201）。這個比法只寫在設計文件，規則裡沒有。
- 我實跑的結果：DR3 用的是新寫法，它引的「這個模式只在修復**還沒 commit** 時成立 —— 8 步迴圈步驟 2 已經 commit 之後…」逐行 `grep -F` 找不到（grepF=False），去掉空白才找得到（stripped=True）。DR1 那句跨進 `> ` 引用行的原句，連去掉空白都對不到。
- 失敗情境：下一個 session 照 security-audit 第 8 步，拿新規則產出的乾跑引文去 `grep -F`。原句明明沒變，跨行的那幾句會被判成「被改了」，接著去重跑分支的乾跑。
- 反過來，乾跑的 agent 為了做到「一字不差」，可能把引文截在行尾。DR4 引的「原生 `EnterWorktree` 工具、CLI `--worktree` 與」正好停在原檔第 9 行的行尾（`skills/worktree-manager/SKILL.md:9`），斷在半句中間。

**Important｜diff.txt:34「太長就只引卡住的那一段」｜這句有兩種讀法，而且照字面做，「兩句互相矛盾」那類發現會引不完整。**
- 兩種讀法：同一步前面把發現分成三類（「哪一句讓它卡住、只能用猜的、或兩句互相矛盾」，diff.txt:114）。所以「卡住」可以讀成「出問題的那一段」，也可以讀成「只限『卡住』這一類」。
- 矛盾類的問題：矛盾天生要兩處原文，新規則只說「不把兩處併成一句」，沒說兩處要各引一段。
- 新寫法臂的實際交回：DR4 的「先用原生」｜矛盾，另一邊是 frontmatter，只在理由欄裡用「與 frontmatter 的「自動啟用」衝突」帶過。DR3 的矛盾條只引了一邊，另一邊（`&&` 遇到預期中的失敗就會中斷）是 agent 自己的推論，原文完全沒引。
- 截斷的副作用：DR4 被截短的引文「原生 `EnterWorktree` 工具、CLI `--worktree` 與」不含它在抱怨的「≥ 2.1.198」。比對子字串會判它對得上，但這段引文支撐不了那條發現。
- 失敗情境：照字面派工後，矛盾條只會帶回其中一邊的原文。主對話用指令核對時只核得到那一邊，「兩句真的互相矛盾」核不到。

**Important｜設計文件 S1.6-1 的過關條件（diff.txt:69）和實際跑的比對（diff.txt:201）不是同一件事。驗證寫的是「全部對得到」，但實際只驗了每條開頭那段引文。**
- 證據：過關條件寫「交回裡「」引的每一段，去掉換行與空白後都對得回原檔」；實際比對寫「取每條開頭「」裡的文字」。

## 處置

- 第 1 條（Important，「一字不差」怎麼核對沒寫，`grep -F` 跨行對不到）採納：規則補上「對不回原檔時先去掉換行與行首的 `>` 再比、再讀原檔那一段，不要直接判成引錯或原文被改了」
- 第 2 條（Important，「卡住的那一段」有兩種讀法，矛盾類會只引到一邊）採納：改成「太長就只引有問題的那一段，互相矛盾的兩句各引各的」。後半句沒有試派，設計文件第 6 項有寫
- 第 3 條（Important，過關條件與實際比對不是同一件事）採納：同 S1.6-a 第 3 條
- Smell（規則假設引文用「」標）採納：規則裡拿掉「「」裡」，改說「引的原句」
- 需要外部查證（原句跨行時 agent 做不做得到一字不差）：沒有另外派。六個乾跑裡 DR1 有一條跨兩行的引文，去掉行首的 `>` 之後對得到
