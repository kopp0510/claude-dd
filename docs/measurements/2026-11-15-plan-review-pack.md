# 計畫審查：計畫與事實放成檔、審查者只拿路徑（2026-11-15）

設計文件 `docs/designs/2026-11-15-speed-cost-design.md` 的 S3。腳本在 `2026-11-15-plan-review-pack/`。

## 要回答的問題

`skills/plan-review/SKILL.md` 改成「主對話把計畫與事實寫成一個檔（審查包），裁決者與審查者的 prompt 只給路徑」之後：

1. 審查者是不是比較早開跑（裁決者不用再把同一份內容寫進每個審查者的 prompt）
2. 裁決者與每個審查者有沒有把檔讀到最後一行
3. 2026-11-14 那條重大還抓不抓得到

起因：`2026-11-15-reviewer-effort.md` 量到四發裡審查者的 Agent 呼叫在第 83–86、158–161、234–236、312–313 秒才出現，每個 prompt 約 1.48 萬字元。

## 方法

- 素材、快照、父 session、`run.sh`、`stats.py`、`timeline.py`、`outside.py`、`deid.py` 都直接用 `2026-11-15-reviewer-effort/` 那一份（不複製）：
  同一份 2026-11-14 的計畫與事實、快照 `b1935bb`、haiku 父 session 派一個 opus 裁決者（`effort "medium"`）、審查者 haiku 明寫 `effort "medium"`。
- 不同的只有裁決者 prompt：`fill.py make … pack` 從改過的 SKILL.md 範本填出來，計畫與事實那一段換成 SKILL.md 第 2 步的那一句讀檔指示；審查包寫在 `<工作目錄>/prompts/<發代號>.pack.md`。
- `fill.py check`（V1）：拿 `b1935bb` 的舊範本照「貼」的填法填，要跟 `2026-11-15-reviewer-effort/judge.txt` 逐位元組相同。這證明 `fill.py` 填的是範本，不是另外寫的 prompt。
- 發代號 `P-med-4`、`P-med-5`（補跑用 `P-med-6`）；新的工作目錄，裡面沒有舊實驗的報告。基準是舊實驗 medium 臂的 `P-med-2`、`P-med-3`。
- 基準與新做法還有一個沒改的共同點：裁決者自己的任務說明都是從檔案讀的（`parent-a.txt`），所以量不到「主對話少貼一次」那一段。

## 判準（跑之前寫死）

三個關卡都過才採用；每發跑完先看 `stats.py` 的作廢檢查（errors 不是空的就作廢重跑），再看關卡。

- **① 派工**（`timeline.py`）：每一發最後一個審查者開始的秒數 ≤ 150（基準 312、313）；每個審查者的 Agent prompt ≤ 3000 字元（基準 14,653–14,862）。
- **② 讀完**（`readcheck.py`）：每一發的裁決者與每個審查者，對審查包的 Read 結果裡有結尾那一行 `<<<審查包結束>>>`。
- **③ 命中**：那條重大（M1，定義照 `2026-11-15-reviewer-effort.md`「正確答案」，機制 (a) 或 (b) 講到其中一個才算）在審查者報告聯集裡 2 發中 2 發。
  1 發 → 補跑第 3 發，3 發中 2 發算過；0 發 → 不採用。
  ③ 只排除大幅退步：基準四發全中，n=2 全中不能證明命中率沒降。結果只寫「幾發中幾發」，不寫「沒退步」。
- ① 或 ② 沒過：先看紀錄檔是哪一句沒被照做，改 SKILL.md 那一句的寫法，補跑 1 發（算進下面的發數上限）；補跑還是沒過 → 不採用。
- 不採用 = 還原 `skills/plan-review/SKILL.md` 並撤掉 CHANGELOG 那一條，量測結果照樣寫。
- 裁決者整發秒數、最後一個審查者結束的秒數、費用照記，**不當關卡**：舊實驗裡審查者自己的耗時從 38 到 229 秒，n=2 時它的波動超過 100 秒。
- 命中由我人工判（我也是改 SKILL.md 的人），每一筆附報告檔與行號。

洩題：`stats.py` 的 `leaky()` 與 `outside.py` 列出的每一筆人工判，判法照 `2026-11-15-reviewer-effort.md`「洩題檢查怎麼判」。
這次要特別看的：暫存區裡有舊實驗存下的報告與當時的裁決報告（都講到 M1），有 subagent 讀到它們的內容，那一發作廢。

## 預算

`claude -p` 最多 3 發；每發跑完累加 `result.total_cost_usd`，開下一發之前確認「累計 + 3.1」不超過 10 美元，超過就停下回報。

## 另外三項不花 `claude -p` 的檢查

- **大檔**（V3）：兩個超過 47 KB、最後一行是結尾句的檔（一個每行短、一個每行約 600 個中文字），各派一個 haiku subagent，只給 SKILL.md 那一句讀檔指示，要它交回結尾那一行的上一行（每份檔不同的隨機字串）。交不回就改指示再試，最多改 2 次，每次的寫法與結果都記；最後用的寫法就是 SKILL.md 裡的那一句。
- **乾跑主對話那一半**（V4）：general-purpose subagent 讀 repo 這份 SKILL.md（不准用 Skill 工具：部署版是舊的），在暫存區的拋棄式目錄照第 1、2 步做到「要送出裁決者 prompt」為止，不真的派。
  三個臂：第 1 輪寫得了檔；第 1 輪寫不了檔（任務說明裡宣告 Write 與會寫檔的 Bash 都被拒）；第 2 輪（附前一輪的裁決報告）。確認輪與重跑都是回第 1 步重送，做法同第 2 輪，不另開臂。
  用指令核對：審查包存在、計畫與來源 `diff` 相同、最後一行是結尾句；它交回的 prompt 不含計畫內文、含路徑與行數、`《…》` 原樣。寫不了檔那一臂要看到標記與計畫內文。
- **貼的那條路**（V5）：opus subagent 拿 `fill.py make … paste` 填出的裁決者 prompt，不真的派，交回它會給第一個審查者的 prompt 全文；我用指令數字元數（要大於材料的 13,426）並 grep 兩個標記。
