## 只准讀這些路徑

- 被審的 repo（快照）：{SNAP}
- diff 檔：{DIFF}
- 這份說明：{SELF}
其他路徑一律不讀（含 `~/.claude/projects/`、`/Users/` 底下任何路徑、{S4} 底下別的東西）。git 指令一律 `git -C {SNAP}`。
派審查者時把這一節原樣轉達給它們。

## 你要做的事

1. 先讀 diff 檔（前段是 `git -C {SNAP} diff HEAD~1 HEAD`，後段是每個被改到檔案的整檔內容，帶行號）。
   被改到的檔一律讀 diff 檔裡那一份；沒被改到的檔照常讀快照。
2. 用 Agent 工具**在同一則訊息裡平行**派審查者：{REVIEWER}，**最少 3 個**，數量你自己定並寫理由。
   給審查者的 prompt 要包含：上面「只准讀這些路徑」整節；diff 檔路徑與「被改到的檔讀 diff 檔裡那一份」；下面「範圍與已跑過的驗證」整段；
   專案規則在快照裡的 CLAUDE.md（根目錄與各層）；
   **審查者的職責：找漏洞、證明這次改動有錯，每條附證據（diff 檔行號或快照檔案行、grep 結果），沒證據的不算**；
   只用手上的資料判斷，需要外部查證的列出來交回、不要自己去抓。不設工具次數上限。
3. **等全部審查者都回來**才往下（還沒全回來就不要寫報告）。某個審查者失敗或沒回來 → 補派，補不了就照實寫進報告。
4. 逐條讀程式碼查證（預設「這條可能是錯的」，不表決），分三類：採納 / 駁回 / 需使用者決定。
   採納項沿用審查者標的級別（Critical / Important / Smells），調級要寫理由。審查者丟進 Not reported 說「既有問題」的，回去看那幾行。
   「行為變了但程式碼、測試、文件都沒寫明哪個才是預期」的，標成需使用者決定，附選項與建議答案。
   審查者列的外部查證項，你能查就查，查不了另列「需要外部查證」。
5. 不准改任何檔、不 commit。

## 交回格式

【派工】派了幾個、各自方向、為什麼這個數量

【駁回】每條：來源代號｜內容｜理由（附查證）
【需使用者決定】每題附選項與建議答案；沒有寫「無」
【需要外部查證】沒有寫「無」
【結論】Critical N / Important N / Smells N（採納數）
